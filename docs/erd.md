# e-Learning Python Platform – Entity Relationship Diagram

This document summarises the database design that underpins the Python learning platform. The goal is to support lessons, structured assessments, certification, and dashboard analytics.

## Core Entities

| Table | Purpose | Key Attributes |
| --- | --- | --- |
| `users` | Stores platform accounts for admins and students. | `name`, `email`, `password`, `student_code`, `is_active` |
| `roles` | Defines permission groupings. | `name`, `display_name` |
| `role_user` | Pivot table assigning one or more roles to a user. | `role_id`, `user_id` |
| `lessons` | Represents a major topic in the curriculum. | `slug`, `title`, `description`, `duration_minutes`, `level`, `prerequisite_lesson_id` |
| `sections` | Breaks a lesson into digestible learning segments. | `lesson_id`, `title`, `summary`, `content`, `video_url` |
| `quizzes` | Assessment containers (pre-test, post-test, practice). | `lesson_id`, `type`, `passing_score`, `time_limit_minutes`, `max_attempts` |
| `questions` | Individual questions for a quiz. | `quiz_id`, `question_text`, `question_type`, `points` |
| `options` | Multiple-choice options for a question. | `question_id`, `option_text`, `is_correct` |
| `quiz_attempts` | Captures each user submission of a quiz. | `quiz_id`, `user_id`, `score`, `max_score`, `percentage`, `status`, `is_passed` |
| `answers` | Records responses within an attempt. | `quiz_attempt_id`, `question_id`, `option_id`, `is_correct`, `awarded_score` |
| `certificates` | Issued when learners complete required milestones. | `user_id`, `lesson_id`, `certificate_code`, `status`, `issued_at` |
| `dashboard_metrics` | Aggregated metrics surfaced in analytics dashboards. | `user_id`, `lesson_id`, `metric_key`, `numeric_value`, `recorded_at` |
| `dashboard_metric_logs` | Audit trail for metric recalculations. | `dashboard_metric_id`, `previous_value`, `new_value`, `change_reason`, `changed_at` |

## Relationships

- **Users & Roles**: Many-to-many via `role_user`. A user can hold multiple roles, and a role can belong to many users.
- **Lessons & Sections**: One-to-many. Each lesson is partitioned into ordered sections.
- **Lessons & Quizzes**: One-to-many. Every lesson owns up to three quiz types (`pre_test`, `post_test`, `exercise`).
- **Quizzes & Questions**: One-to-many. Questions are ordered within a quiz.
- **Questions & Options**: One-to-many. Each question contains multiple answer choices with at least one marked correct.
- **Quizzes & Attempts**: One-to-many. Users can attempt a quiz multiple times, constrained by `max_attempts`.
- **Attempts & Answers**: One-to-many. Each answer records the learner’s selection for a question inside a specific attempt.
- **Users & Quiz Attempts**: One-to-many. Attempts are tied to the user who submitted them.
- **Lessons & Certificates**: Certificates represent completion evidence for a union of `user` and `lesson`.
- **Dashboard Metrics**: Metrics can be user-specific, lesson-specific, both, or global (when `user_id` and `lesson_id` are `null`). Logs track historical changes to each metric.

## Notes

- All primary entities use unsigned big integer IDs generated by Laravel migrations.
- Timestamps are standardised with `created_at` and `updated_at` columns across tables.
- Constraints enforce referential integrity and cascading deletes, ensuring orphan records are avoided when parent entities are removed.
- Seeders populate nine Python lessons (introductory through advanced), standard assessment content, baseline user accounts, quiz attempts, certificates, and dashboard sample data to power analytics views.
